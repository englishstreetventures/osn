# Translation (i18n) — the x18n checker

No package translates its interface yet. Every screen renders English, and no package depends on an i18n library or has locale files. The first planned translation is cire's guest interface (`englishstreetventures/osn#1409`).

[x18n](https://x18n.dev) is the checker for translation files. It reads the locale files and the translate calls in the code, and reports missing, empty and unused keys and coverage per locale. It detects most i18n libraries through its presets, so it needs little config.

## What is in place

| Piece | State |
|---|---|
| [`x18n.config.ts`](../../x18n.config.ts) at the repo root | `sourceLocale: "en"`, `resources: []` |
| `@x18n/cli` dependency | Not installed |
| `i18n:check` script | None |
| CI job or git hook | None |

With no resources, `check` passes and reports `en` at 100%.

## Running it

```bash
bunx --bun @x18n/cli@0.1.3 doctor        # what x18n detects and which config values it read
bunx --bun @x18n/cli@0.1.3 check --json  # errors, warnings and coverage per locale
```

> [!warning]
> Always name the scoped package with an exact version. `bunx x18n` runs an unrelated package of that name from npm whenever the local bin is missing. The exact version also keeps the run inside the 3-day `minimumReleaseAge` in `bunfig.toml`; 0.1.3 published 2026-10-28.

`doctor` lists `config origins`. Each key set in the config shows `user`; a key that shows anything else was misspelt and x18n fell back to its default. The config is a plain object with no `defineConfig` import, because `@x18n/core` is not a root dependency and the isolated linker does not hoist it.

## Why it is not installed yet

A root dev dependency costs a full release for a tool that checks nothing yet:

- `scripts/deploy-surfaces.ts` counts root `package.json` and `bun.lock` as content every surface builds from. A change to either redeploys every dev surface on merge and puts every surface into the next production release.
- `@x18n/cli` 0.1.x pulls in svelte, the Vue SFC compiler, a second `oxc-parser` with its platform binaries, MCP server and client packages, `h3` and `crossws`. It also meets the root `yaml` and `postcss` overrides.

The first branch that adds locale files changes the lockfile anyway, so it pays that cost once.

## Adding the first locale files

The branch that adds them:

1. Adds a `resources` entry to `x18n.config.ts` with the file pattern, such as `{ pattern: "cire/invites/src/locales/{locale}.json" }`, and the presets for its library if `doctor` does not detect them (names on [x18n.dev/presets](https://x18n.dev/presets)). `doctor` must then list every locale file.
2. Adds `@x18n/cli` as an exact-pinned root dev dependency: `bun add -d --exact @x18n/cli@<version> --cwd .`, then `bun install --frozen-lockfile`. Check the lockfile with `scripts/lockfile-evidence.sh` and run `bun audit --audit-level=high`, as [[contributing]] describes.
3. Adds `"i18n:check": "x18n check"` to the root scripts and lists it in [[commands]].
4. Adds `x18n check` to CI.
5. Updates this page: the table above and the commands.

x18n covers interface text only. For cire, `englishstreetventures/osn#1409` rules out machine translation of what organisers write, such as invite stories, events and questions; the guest designs that render it are in [[cire-invite-designs]].
