# Lint-warning ceiling for scripts/guard-lint-warnings.sh.
#
# The single source of truth for how many warning-severity diagnostics
# `bun run lint` (oxlintrc.json's categories) may report across the whole
# monorepo. Nothing else names this number — not `.github/workflows/ci.yml`,
# not a script argument.
#
# @see wiki/conventions/bundle-size-guards.md — how this number moves.
#
# A pull request never lowers it. A branch that removes warnings leaves
# this file alone: CI passes a count below the ceiling, and
# .github/workflows/release.yml lowers the number to the measured count on
# main after the merge (scripts/guard-lint-warnings.sh --lower-to), in the
# same commit as the version bumps. Pull-request CI holds every branch to
# the warning count of its base instead (--base HEAD^1), so a ceiling that
# has not been lowered yet lets nothing through.
#
# A pull request raises it only for warnings it adds on purpose: set the
# number to the one the failing guard names, and put the branch and date in
# the trailing comment. Two raises at once then collide as a real merge
# conflict rather than silently agreeing on the same leading number.
#
# One value, alone on the first non-comment, non-blank line — nothing else
# in this file is read.

878   # lowered by scripts/guard-lint-warnings.sh --lower-to, 2026-10-16
