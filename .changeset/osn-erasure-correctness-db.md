Add the schema account erasure needs to be undone and to hold handles. New table `handle_holds` (`handle`, a keyed hash and the primary key; `account_id`, set while the deletion is pending; `release_at`; `created_at`), indexed on `account_id` and `release_at`, with two CHECKs: a row has an account or a release, never both and never neither, and its handle is 64 characters. `deletion_jobs` gains `restore` (what a cancel puts back), `choices` (the person's answers for owned organisations), `hard_delete_failed_at` and `job_id` (a random id naming the job). `security_events` gains `security_events_created_at_idx` for the retention sweep. `organisation_members`' `org_members_org_idx` becomes `org_members_succession_idx` on (`organisation_id`, `role`, `created_at`, `id`), the order the hard delete picks a successor in; a read on the organisation alone uses its prefix. One migration, `20261115054558_account_erasure_restore.sql`; every new column is nullable and the new table starts empty. The test-schema emitter (`@osn/db/testing`) now writes CHECK constraints.
