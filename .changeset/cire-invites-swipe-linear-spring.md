The event sheet's swipe settles on a CSS transition instead of the `motion` library, and `motion` leaves the guest site. At release the sheet samples the same critically damped spring — a 0.3s response, started at the finger's speed — into a `linear()` easing and runs it as the panels' and the badge's transition, so a flick still carries on and a slow release still does not jump: the first frame after release moves at the speed the finger had, and a flick fast enough to pass the panel's rest stops on it. An engine without `linear()` (Chrome before 113, Safari before 17.2) gets a `cubic-bezier()` with the same first slope that never passes the rest and, released moving away from it, runs no further the wrong way than the spring. The settle's time now follows `--motion-scale`, and the reduced-motion clamp lands it at once, so the sheet no longer checks `matchMedia` for it. A touch on a settling swipe still catches the panels where they are on screen. The event sheet's client chunk is 17910 bytes gzip smaller (37593 to 19683). The SSR stub that kept `motion` out of the Worker goes with it.
