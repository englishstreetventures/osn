Squash the cire D1 migration chain into a new baseline,
`cire/db/migrations/0001_initial.sql`, generated by
`scripts/cire-db-baseline.ts`. A new database builds the whole schema in one
migration of 150 schema statements instead of replaying 200; the D1 cost line
stays at 200.

The 26 files the squash moved, the October baseline among them, live in
`cire/db/migrations-archive/long-lived/` with their names and bytes unchanged.
Dev's and production's ledgers recorded each by name and hash, so the cire
stack hands both databases that chain as written (`CIRE_DB_LONG_LIVED_MIGRATIONS`,
`CIRE_DB_PRODUCTION_MIGRATIONS`): the release that ships the squash writes
nothing to either, and needs no production step first. An investigation stage
gets the baseline. One whose database was built before the squash is refused
before any write; delete that database in the dev account and deploy the
stage again.

`db:push` accepts a local database built from the October baseline that holds
every long-lived migration, and refuses one that lags, as before.
