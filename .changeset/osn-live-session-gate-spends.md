Every route that spends a step-up token now answers `409 { error: "session_stale" }` before it reads the token unless the caller holds a live session (its session cookie, or its access token's `osn_sid` binding, names an unrestricted, unexpired session of the account): `DELETE /account`, `GET /account/export`, `POST /account/security-events/:id/ack` and `/ack-all`, `DELETE /totp`, `PATCH /passkeys/:id` and `DELETE /passkeys/:id`. So do `POST /account/restore`, `DELETE /sessions/:id`, `POST /sessions/revoke-all-other` and `DELETE /oidc/connections/:clientId`, before anything is revoked or withdrawn; `POST /sessions/revoke-all-other` serves a caller whose access token's `osn_sid` names a live session even with no session cookie, and passkey registration's begin refuses a restricted recovery caller whose session names no row before it reads a step-up token.

The session the check finds is the one sign-out-everywhere and a passkey deletion spare, and the one an account deletion keeps as its cancel handle, by the family the check found, so a renewal in another tab before the sweep keeps the device that can cancel. Of two concurrent deletes of an account's two passkeys, the one that finds its passkey the last is refused and records nothing. The check lives in `lib/live-session.ts`; `createAccountExportRoutes` takes the cookie configuration as its second, required argument; `deletePasskey` takes the caller's session hash as a string; `requestErasure` takes `cancel: { sessionId, familyId } | null`; `resolveLiveOrdinarySession` answers the session's hash and family.
