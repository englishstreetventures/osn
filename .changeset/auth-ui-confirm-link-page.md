`@osn/auth-ui` gains `ConfirmLinkPage` (`@osn/auth-ui/ConfirmLinkPage`, and from the barrel): the page an emailed link opens for sign-up, recovery, step-up and email change. It asks the person to pick the number shown on the waiting screen from the host's `candidates` (three to five, all different, each one to six digits, passed as osn-api sends them), drawn in the order given in tabular figures and kept from page translation; any other list draws the expired page. Tapping a number is the confirm: `onConfirm` receives exactly that number, never on a mount, a prop change or a timer, and every choice disables itself so one tap is one call. "I didn't ask for this" sends `null` and a `declined` answer shows "Cancelled". An answer must fit what was sent; every refusal shows the same expired page; a thrown error shows a fixed line and Try again, which sends the same number, or the same decline, again, and "I didn't ask for this" stays open, sending `null` as a new attempt. Step-up's expired page keeps its warning to sign out the other sessions. With `typeNumber`, which recovery's and step-up's hosts pass, the page asks the person to type the number instead: one labelled field for up to six digits that refuses any other insertion and never rewrites what was typed, Confirm (or Enter) once it holds one to six digits, and the entry sent exactly as typed. `initialOutcome` opens the page on `confirmed` or `expired` with no numbers, and the props type requires one of `candidates`, `typeNumber` and `initialOutcome`, never `candidates` with `typeNumber`. One polite output says each change aloud, the heading takes focus on every change, and a call still running after 10 seconds says so. Nothing renders it yet.
