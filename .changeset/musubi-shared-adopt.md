Every one-time code is typed into `OtpInput`'s boxes, tied to its error line, and every loading placeholder is `Skeleton`.

- `@osn/auth-ui`: `StepUpDialog`'s two code steps and `ChangeEmailForm`'s code are a row of `OtpInput` boxes under a span label, in place of a single `Input`; each code step puts focus in box 1 as it opens. Every row of code boxes (`Register`, `RecoveryLoginForm`'s two, `TotpView`, `StepUpDialog`'s two, `ChangeEmailForm`) names its group by its label (`aria-labelledby`; `Register`'s keeps "Verification code") and its error line by `aria-describedby`, on every box. The boxes are marked invalid, with the danger edge, only for a `400` or `422` refusal other than the verification check, so a wait or an outage ties the line without calling the code wrong. After such a refusal sent with Enter, `Register` puts focus back in box 1 when focus is on the page or still in the row, as WebKit can leave it on the disabled box. `PasskeysView`, `SessionsView`, `TotpView` and `RecoveryCodesView` show `Skeleton` while they load, in a region marked `aria-busy`, in place of "Loading…" and a hand-drawn pulse; each reads its resource's `state` before its value, so it never joins a host's `Suspense` boundary or throws a failed read, and `StepUpDialog` reads `GET /totp/status` the same way, so opening a step-up never swaps its host for the host's fallback. `PasskeysView` and `SessionsView` disable their actions while a list they have shown is read again, so a passkey just deleted or a session just revoked cannot be acted on. `TotpView`'s enrolment step drops its border and padding below `md`, and `StepUpDialog` its side padding, so a code row takes the panel's whole column on a phone; a panel's header action wraps under its heading when the two do not fit.
- `@musubi/social`: Connections, Discover, Organisations, an organisation's head and members, Connected apps, and the fallbacks of Settings' Security and Connected apps tabs and `/authorize`'s sign-in frame draw `Skeleton` in place of "Loading…" lines and `bg-muted/50 animate-pulse` blocks, each in a region marked `aria-busy`. `/authorize`'s placeholder takes the shape of the half that leads, sign-up's four fields for `reason=create`. Connected apps says a failed list in its own line instead of throwing to the page's error boundary, and keeps its rows on screen while it reads them again after a revoke. The Settings Security tab shows each panel's own placeholder rather than its fallback for the whole tab. `DESIGN.md` gains the loading rule, that what replaces a placeholder, an error line and a step that replaces another arrive with no fade, and the code boxes' widths at 320px, and no longer lists `Badge`, which Musubi does not draw; the token-contract browser test drops its `Badge` case. A new browser test opens the step-up's code step in Settings → Security at 320 and 1440px and checks the code row's width and that no button runs past the card.
- `@tools/lab`: `SkeletonGrounds` drops the half-strength placeholder Musubi drew by hand.
