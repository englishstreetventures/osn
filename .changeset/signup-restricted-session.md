A sign-up's session is restricted until the new account has its first passkey. The completing status poll now issues a session whose access tokens carry `osn-recovery`, so only `/passkey/register/*` accepts them; its cookie is no signed-in session to `/authorize` or to a `/token` grant for anything but its own rotation, and it lives 15 minutes. Its row records `signup`, which takes nobody past the step-up gate and stamps the first passkey `webauthn`. Enrolling lifts the restriction in the batch that inserts the passkey, so the two commit together, and the sign-up funnel counts the first passkey as its `passkey_enroll` step. `/passkey/register/begin` and `/complete` answer 401 to a restricted token whose session a passkey has already lifted, so a tab that missed the answer renews into the ordinary session. Migration `20261126014432_end_passkeyless_sessions` ends the ordinary sessions of accounts made before this that never added a passkey, sparing restricted sessions and any account with a deletion job; those people come back through the emailed recovery link. Migration `20261126022912_sessions_restriction_known` adds two triggers that refuse a session row whose `restricted_amr` is not `webauthn`, `otp`, `totp` or `signup`, or is set while `restricted_until` is NULL. `@osn/client` exports `isRestrictedToken`, and its cold start publishes no session for a restricted cookie.
