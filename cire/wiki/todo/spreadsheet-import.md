New `ChangeScope` (`both`|`events`|`guests`) in `schemas/import.ts` is threaded body → `diffAgainstDb(options.scope)` → the change row's summary → apply's re-diff → revert. **An absent sheet is not an empty sheet**: the scope SUPPRESSES the unmanaged half of the diff rather than reconciling it against an empty desired state (which would delete every household). See `[[guest-event-editor]]` §3.1.

- [x] **E9 — the UTC offset leaves the CSV schema** (shipped 2026-08-06, see `[[guest-event-editor]]` E9) — reported from the portal: event editing still showed *both* a timezone and a UTC offset. It did, in four places — the schedule editor's summary rows printed the raw stored `…+11:00`, the drawer's zone hint appended "— UTC+11:00 on this date", the events table's can't-format fallback printed the stored string, and the **template + parser + guidance still asked for an offset `Start` next to a `Timezone` column**. An event's time is now stated one way everywhere: a **local wall clock plus an IANA zone**. The template emits `2026-11-14T15:00`; new `api/src/lib/event-time.ts` reads the local clock out of a cell (**discarding any offset or `Z` — the Timezone column is authoritative**) and stamps the offset the zone is on for that event's own date, so a stale `+10:00` on a November Sydney row is corrected rather than believed; the parser now **requires a resolvable IANA zone** (`isKnownTimeZone` — `AEST` / `Sydney` / fixed-offset spellings are rejected), which it needs for the stamp and which an unresolvable zone would have broken on the guest site anyway (`Intl` throws on an unknown `timeZone`); pre-PR review caught **P-C1** (see `[[todo/perf]]`) — the row loop resolved the same zone 3× per row through the deliberately-uncached `canonicalTimeZone` — fixed with a module-scoped memoized cache in `event-time.ts`. Both re-importable exports strip the offset back off, proven lossless by the existing export→parse→diff **fixpoint** test. Organiser-side, `lib/event-display.ts` owns one formatter for the table and the editor rows, and its degraded paths print the wall clock rather than the raw value — including for a **date-only draft**, which `Date` reads as UTC midnight and which used to render as an invented "11:00 am" on a row whose save was blocked for having no time. **The stored column is unchanged**: `events.start_at` keeps its derived offset because the guest site reads it as an instant (render, ICS, Google Calendar) and `event-order.ts` sorts on it. The offset is now strictly internal — derived, never typed, never displayed.

**The editor chain is complete.** Slice-by-slice detail lives in `[[todo/platform]]` (PR 5a) and the design in `[[guest-event-editor]]` §10.

Source spreadsheet has these columns: `Family ID, Guest First Name, Guest Last Name, Family Name, Catholic Wedding, Hindu Wedding, Reception, Mehndi`. Row grouping is by `Family Name`; only the last row of each family carries a Family ID in the source sheet (we ignore that — Cire generates its own `publicId`). Each guest row has booleans per event.
