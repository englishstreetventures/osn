An answer is applied only for the session it was asked for. When a sign-in is adopted, the page logs out, or the session ends (here or in another tab) while a cookie grant, renewal, profile switch or request is out, its late answer changes nothing: `loadSession` resolves to the session the page holds then, or `null`, and a renewal, switch, delete or `authFetch` made for the old session rejects with `AuthExpiredError` without storing, resetting or ending anything. A request made as one account is never renewed or sent again as another, and its answer is not handed back. A renewal or bootstrap started for the old session is never joined by a call for the new one, which waits that grant out and sends its own; a grant whose session has gone stops retrying; the old session's renewal pause does not carry over. Before saving an answer the service reads the stored account, and if another tab has stored another sign-in or none since, ends this page's session instead of writing over it. `refreshSession` gains `AuthExpiredError` in its error type, and a refused `refreshSession` now ends the session itself.
