`queries.sql` runs again under DuckDB 2.0. Its `cards` view now declares the card's shape instead of inferring it, with the five objects a card keys by data (`spend.by_model`, `spend.effort`, `interaction.tool_calls`, `interaction.skills`, `interaction.subagents`) read as maps, so a card holding two names that differ only in case (`Bash` and `bash`) no longer stops the script. The nine queries return the same rows over the committed cards. A new test fails when the declared shape and the card the collector writes disagree, and the DuckDB tests now turn off DuckDB's agent mode, which had hidden the error from them.

`interaction.corrective_turns` now counts only the prompts a person sent while the agent was still working, and the card's `schema_version` is 4. A turn sent after the agent stopped (a new task, an answer to its question, "continue") no longer counts, so a long session that took on new work turn by turn no longer reads as a badly briefed one. A queued record counts as a person's only when the harness labels it so (`origin.kind: "human"` or `humanTurn: true`; `commandMode: "prompt"` on older transcripts), and the CLI warns when a queued record carries a sender it does not know. `report` and `queries.sql` read the count on a card before version 4, or on one with no human turn, as unknown, and say how many cards their corrections median covers. The PR-body line reads "N (M sent mid-turn)".

The spend of agents a Workflow run starts now lands on the card of the branch their task names. A script starts these agents, not an `Agent` call, so the collector reads the `TASK-BRANCH:` line from the agent's own task, the record whose first line is the harness's `[Workflow harness — computed task]` header, within its first three lines and with the harness's indentation allowed there only. It never reads the harness's relay of the user's request or anything after the agent's first reply. The run's `journal.jsonl` is no longer read, so it no longer adds to the warning about subagent transcripts that land on no card.
