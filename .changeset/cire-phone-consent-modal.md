"@cire/invites": minor
---

The first-visit privacy prompt on an invite is now a dialog the guest answers before going on, at every screen size, instead of a banner along the bottom of the screen. Once answered, nothing covers the invite's opening screen, where the gala design puts the couple's names. Escape, the back gesture and a tap outside the dialog do not close it; only an answer does. The highlighted answer is "Accept necessary", which switches off everything that is not needed to run the invite; "Accept all" and "Choose" sit beside it in a plainer style. The dialog opens on its heading rather than on an answer, and links to the privacy notice and the terms, which both still show the prompt as a banner so a guest can read them before deciding. On those pages the banner no longer covers the end of the notice or the footer, and keyboard focus is kept clear of it. The venue map and the Pinterest moodboard now stay off until the guest allows them: before that, and after a refusal, the map card and the link to the moodboard stand in, and the prompt's text says so and names "Accept all" as the way to turn them on. The privacy notice says the same. The privacy choices dialog calls the refusal "Accept necessary" too, instead of "Reject all". On the live site the privacy choice is now read only from this site's own secure cookie: a same-named cookie set by another cireweddings.com site is ignored, so a guest whose choice was stored only under the old name is asked once more. A page brought back with the browser's back button checks again for an answer given on another page. The hero's scroll chevron no longer moves up for the banner, since no banner sits over an invite any more.
